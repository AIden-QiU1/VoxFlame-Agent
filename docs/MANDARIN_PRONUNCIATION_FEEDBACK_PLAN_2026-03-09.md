# VoxFlame 中文语训反馈方案（2026-03-09）

> 目标：把“训练页”从泛化的录音采集页，收敛成面向中文普通话场景的发音反馈页。这里讨论的是中文语训，不是照搬英文 phonics / IPA 训练路径。

---

## 1. 结论先行

如果 VoxFlame 要做类似“雀说语训”的能力，近期最合理的路径不是直接输出英文式发音评分，而是做一套 **中文普通话的拼音 + 音节 + 混淆模式反馈系统**。

近期应该优先反馈的不是抽象的“pronunciation score”，而是：

1. 这句话的目标汉字和拼音是什么。
2. 用户这次更像读成了什么。
3. 问题更像出在声母、韵母、声调，还是漏字 / 多字。
4. 本次最值得先改的 1 到 2 个点是什么。

---

## 2. 为什么中文不能照搬英文训练逻辑

中文普通话的训练单位更适合按这四层处理：

1. 句子 / 场景层
2. 字词层
3. 音节层（拼音）
4. 声母 / 韵母 / 声调层

而不是一上来就按英文那种：

- 单词音标
- phonics
- 英文最小对立对

来做。

对 VoxFlame 的含义是：

1. 首页和训练页都应该默认展示汉字 + 拼音，而不是 IPA。
2. 建议用中文的可执行提示，例如“平翘舌”“前后鼻音”“n/l”“送气 / 不送气”“声调可能不稳”。
3. 反馈要围绕普通话音节结构，而不是英文音素教学。

这是基于《汉语拼音方案》和普通话测试标准做出的实现判断。

当前仓库并不是从零开始：

1. [frontend/src/lib/corpus/sentences.ts](../frontend/src/lib/corpus/sentences.ts) 已给每条训练语料预留了 `pinyin` 字段，但目前基本为空。

这意味着近期真正该做的不是“先找一个英文发音评分 SDK”，而是：

1. 把训练语料补齐拼音元数据。
2. 把中文音节级对照做出来。
3. 把用户混淆模式写回 memory。

## 4. 中文训练页应该反馈什么

## 4.1 目标层

每次训练先明确显示：

1. 目标句子
2. 逐字拼音
3. 本次练习重点

例如：

- 目标句：`我想喝水`
- 拼音：`wo3 xiang3 he1 shui3`
- 重点：`x/sh`、`ang`、三声

## 4.2 结果层

录音结束后，不应该只说“上传成功”。

至少应该给出：

1. 系统听到的句子
2. 对应拼音
3. 和目标句相比，差异落在哪几个字 / 音节

## 4.3 建议层

建议要尽量压缩成用户能立刻执行的 1 到 2 条，而不是一次性列满。

建议的表达风格应更像：

- `“你” 这次更像 “李”，重点再练 n/l 区分`
- `“是” 更像 “四”，可以先练平翘舌`
- `“帮” 更像 “班”，这次重点看后鼻音 ang`
- `声调可能不稳，先慢读，再分开练这两个字`

而不是：

- 一大串英文音标
- 一大段不可操作的语音学术语
- 一次给 7 到 8 个问题点

## 5. 近期最值得支持的中文错误类型

初期不要贪全。先做最影响沟通、最容易解释的几类：

### 5.1 声母混淆

1. 平翘舌：`z/zh`、`c/ch`、`s/sh`
2. 鼻音 / 边音：`n/l`
3. 送气 / 不送气：`b/p`、`d/t`、`g/k`、`j/q`、`z/c`、`zh/ch`

### 5.2 韵母混淆

1. 前后鼻音：`an/ang`、`en/eng`、`in/ing`
2. 复韵母或介音相关混淆：如 `uo/o`、`ia/ua`、`i/u/ü`

### 5.3 声调问题

1. 调值不稳
2. 二声 / 三声混淆
3. 四声落不下去

### 5.4 句级问题

1. 漏字
2. 多字
3. 顺序错误
4. 低置信识别，无法判断具体发音点

## 6. 中文语训的 UI 建议

## 6.1 跟读页

页面应包含四块：

1. 目标句卡片：汉字 + 拼音
2. 本次重点标签：如 `平翘舌`、`前后鼻音`、`声调`
3. 录后结果区：目标 / 听成 / 差异
4. 建议区：只展示最关键的 1 到 2 条

## 6.2 拼音展示方式

建议默认同时保留：

1. 带声调数字的拼音，便于程序处理，如 `shui3`
2. 适合用户阅读的拼音，可后续转成带声调符号

初期不建议把 IPA 放进主界面。

## 6.3 反馈层级

建议按“从易懂到专业”渐进：

1. 默认：只看结论和建议
2. 点开后：看目标拼音 vs 识别拼音
3. 再点开：看更细的声母 / 韵母 / 声调标签

## 7. 技术实现路径

## 7.1 语料层

每条训练语料至少补齐：

1. `text`
2. `pinyin_syllables`
3. `tone_numbers`
4. `focus_tags`
5. `difficulty`
6. `likely_confusions`

当前 [frontend/src/lib/corpus/sentences.ts](../frontend/src/lib/corpus/sentences.ts) 的 `pinyin` 字段应从空字符串升级为真正可用的元数据。

## 7.2 对照层

训练流程建议改成：

1. 目标句 -> 目标拼音
2. 用户录音 -> ASR 结果
3. ASR 结果 -> 拼音
4. 按字 / 音节做对齐
5. 输出错误标签

初期先做 **文本 / 拼音级对照**，不要一开始就承诺“纯音频级精准发音诊断”。

## 7.3 建议生成层

建议采用两段式：

1. 规则层：判断是 `n/l`、`zh/z`、`an/ang`、声调问题还是漏字
2. 文案层：把规则翻成简短中文建议

这里 LLM 更适合做“表达”和“归纳”，不适合一开始就做唯一判官。

## 7.4 记忆层

每次训练后，把这些信息写回个体记忆：

1. 高频混淆模式
2. 近期最常出错的音节
3. 某些场景下更容易出错的词
4. 已经改善的模式

这样训练页和实时沟通页才能形成飞轮。

---

## 8. 哪些判断初期不要乱做

1. 不要输出“医学诊断结果”。
2. 不要把一次录音的波动直接说成长期问题。
3. 不要默认把方言、变调、轻声、儿化一律判错。
4. 不要用英文口音训练思路强行解释中文发音问题。
5. 不要一次性给太多建议，避免挫败感。

---

## 9. 推荐的分阶段实现

### Phase 0：补中文元数据

1. 补齐训练语料拼音
2. 给句子加 `focus_tags`
3. 页面先把目标句 + 拼音展示出来

### Phase 1：做最小可用反馈

1. 目标句 / 识别句对照
2. 拼音差异对照
3. 基于常见混淆集输出 1 到 2 条中文建议

### Phase 2：个体化训练

1. 训练历史进入 memory
2. 自动识别用户常见混淆模式
3. 生成个性化练习集

### Phase 3：再考虑更强的声学层

1. 声调轮廓
2. 更细粒度的音节边界
3. 更可靠的音频级反馈
