# 中文训练语料来源调研与句长建议

> 更新日期：2026-03-19

## 结论先行

- `生活场景监督句` 和 `音韵强化句` 应该拆成两条来源链，不要混成一个池。
- 当前产品口径收口为：`用户录入页` 句长默认控制在 `5-20` 个汉字。
- `著名中文文章` 很适合做内部 `音韵强化池`，但不适合直接充当用户前台场景句。
- 公开服务网页适合补 `设备 / 办事 / 就医 / 急救`，但对 `开口先说 / 家里需要` 这类真正高频的辅助沟通起手句覆盖明显不足，后续仍要补 `AAC / 对话转写 / 自有授权句库`。
- `Context7` 不适合直接获取语料正文。它适合查软件文档，不适合替代网页抓取、OpenSLR、Hugging Face 或本地转写文件导入。

## 推荐来源分层

### 1. 标准转写库

适合做什么：

- 作为监督数据主骨架
- 补规范转写、音频质量和口音覆盖
- 优先提供“能直接训练 ASR”的句子与转写

代表来源：

- AISHELL-1：`https://openslr.org/33`
- ST-CMDS：`https://openslr.org/38`
- MAGICDATA Read Speech：`https://openslr.org/68`
- WenetSpeech：`https://openslr.org/121`
- Common Voice zh-CN：`https://commonvoice.mozilla.org/zh-CN/datasets`
- SeniorTalk：`https://huggingface.co/papers/2503.16578`

判断：

- `AISHELL-1` 适合补规范普通话读句，但生活感不够强。
- `ST-CMDS` 很适合补短指令和设备控制句。
- `MAGICDATA` 的文本域更接近真实使用，包含问答、短信、设备控制等，更适合打散后进入训练页候选池。
- `WenetSpeech` 天然适合弱监督或半监督，不适合原样进入用户录入页，但适合做“弱监督池/预训练池”。
- `SeniorTalk` 非常适合补“老人/慢速/自然对话”风格，对我们这类真实沟通产品很重要。

### 2. 普通话规范材料

适合做什么：

- 校准声母、韵母、声调、轻声、儿化、语流音变
- 约束“标准普通话”方向，而不是只靠互联网自然文本

代表来源：

- 教育部普通话水平测试试卷：`https://www.moe.gov.cn/moe_879/moe_329/moe_66/tnull_586.html`
- 教育部 2023 测试规程：`https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202302/t20230210_1043384.html`

判断：

- 这类材料告诉我们“测试与训练应该覆盖什么”，尤其是：
  - `单音节字词`
  - `双音节词语`
  - `400 字短文朗读`
  - `无稿说话`
- 但这类材料不适合直接整段搬到训练页，必须先拆成中短句再筛。

### 3. 真实生活网页

适合做什么：

- 拉近用户感知
- 补“办事、设备、出行、急救、就医”等现实场景表达
- 提升用户愿意录的概率

代表来源：

- Apple 无障碍与设备帮助页
- 12306 购票/改签/退票说明
- 医保办理指南
- 红十字应急救护科普

判断：

- 这类来源非常适合 `手机设备 / 出门办事 / 紧急情况 / 看病拿药`。
- 但网页噪声很多，必须经过：
  - 页面抓取
  - 文章打散
  - 菜单/页脚/版权噪声清洗
  - 句长筛选
  - 场景归类

### 5. 人群与角色来源

适合做什么：

- 补 `学生 / 老人 / 课堂 / 照护者 / 职业角色`
- 让训练页不只按“场景”分，还能按“谁在说”分

代表来源：

- SeniorTalk：`https://huggingface.co/papers/2503.16578`
- ChildMandarin：`https://huggingface.co/datasets/BAAI/ChildMandarin`
- 居家养老服务项目：`https://www.zjg.gov.cn/zjgszwz/zcfglnr/202307/e5d22bcf50144ce9b36e8ba952ff3ada.shtml`
- 老年护理服务标准：`https://www.beijing.gov.cn/ywdt/zybwdt/202211/t20221113_2857555.html`
- 家庭护老者培训：`https://www.lg.gov.cn/bmzz/bjjdb/tbgz/content/post_10773661.html`

判断：

- `老人` 方向已经有相对靠谱的公开来源，适合继续深挖。
- `学生 / 课堂` 方向可先从教材、儿童对话和课堂话语页面切入，但更理想的仍是拿到真实课堂语音转写或授权文本。
- `职业` 方向更适合从官方帮助页、工作流程说明、服务 FAQ 和岗位培训材料里抓真实短句，而不是自己想象角色台词。

### 4. 著名文章与声律材料

适合做什么：

- 补音韵、节奏、声调变化和朗读稳定性
- 做内部 `phonology pool`

代表来源：

- 声律启蒙：`https://zh.wikisource.org/wiki/聲律啟蒙`
- 笠翁对韵：`https://zh.wikisource.org/wiki/笠翁對韻`
- 木兰诗：`https://zh.wikisource.org/wiki/木蘭詩`
- 桃花源记：`https://zh.wikisource.org/wiki/桃花源記`
- 岳阳楼记：`https://zh.wikisource.org/wiki/岳陽樓記`
- 醉翁亭记：`https://zh.wikisource.org/wiki/醉翁亭記`
- 兰亭集序：`https://zh.wikisource.org/wiki/蘭亭集序`
- 出师表：`https://zh.wikisource.org/wiki/出師表`
- 滕王阁序：`https://zh.wikisource.org/wiki/滕王閣序`

判断：

- 这类文本不应该直接当“用户场景标题”。
- 但它们非常适合打散成 `5-20` 字的内部补充句池，用来提高声韵调覆盖和朗读节奏稳定性。

## 句长建议

### 当前范围

- 默认句长：`5-20` 个汉字

### 依据

#### 1. 用户录音负担

- 太短的句子（`<5` 字）音系信息太少，容易过度模板化，也不利于后续模型学到连读和短语边界。
- 太长的句子（`>20` 字）会明显增加换气、阅读、记忆和对齐负担，尤其不适合构音障碍用户、老年用户和疲劳场景。

#### 2. 中文移动短句经验

- Stanford Mandarin phrase set 的中文短语长度范围是 `3-15` 个字，平均约 `8.1` 个字，说明移动语音输入任务的自然短句本来就偏短。

#### 3. 中文语音库风格

- `ST-CMDS` 这类设备/命令库本身就是短口令。
- `MAGICDATA` 虽然文本域更丰富，但也以问答、短信、控制句为主，适合拆成短句。
- `SeniorTalk` 这类自然对话库说明真实口语往往不是长篇整段，而是较短轮次、节奏分明的句子。

#### 4. 普通话测试结构

- 教育部普通话测试并不是只考长文，而是把 `单音节`、`双音节`、`朗读短文`、`自由说话` 分开设计。
- 对训练页来说，更合理的是把“标准文章”拆成一批 `5-20` 字的中短句，而不是强迫用户整段朗读。

## 本轮脚本与实跑结果

### 已落地脚本

- `scripts/corpus/fetch_public_corpus_sources.py`
  - 抓公开网页快照
  - 输出 `_fetch_report.json`
  - 输出 `_local_manifest.json`

- `scripts/corpus/build_mandarin_scene_corpus.py`
  - 从本地文件或 URL 读入
  - 打散文章
  - 做网页噪声清理
  - 按句长、场景、常用程度、音系覆盖打分
  - 输出场景句库

- `scripts/corpus/build_phonology_article_corpus.py`
  - 专门把经典文章打散成音韵强化句库
  - 不再强行归到生活场景

  - AAC 领域来源

- “著名中文文章 -> 打散成可录中短句” 这条路是成立的。
- 后续需要继续做一层更细的白名单清洗，去掉个别标题、页脚和站点残留。

## 产品与工程建议

### 产品

- 训练页不应只有“场景”一种入口，而应该同时包含：
  - `日常与出行`
  - `看病与求助`
  - `人群与角色`
  - `设备与数字`
  - `发音与朗读`
- `日常与出行` 仍然是训练页最该优先扩充的真实入口，因为它最接近用户“今天就会用”的表达。
- `人群与角色` 适合承接 `学生 / 老人 / 课堂 / 照护者 / 服务岗位` 这类更有身份感的真实表达，不必继续塞回生活场景池。
- `发音与朗读` 可以直接成为训练页里的一个正式分类，不必只做隐藏池。
- 生活场景句负责“愿意录”，音韵朗读句负责“补音韵音调覆盖”，两者应该并存。

### 当前训练页现役大类统计

前端现役真实句库当前已收口为 5 个大类：

- `日常与出行`：80 句
- `看病与求助`：50 句
- `人群与角色`：80 句
- `设备与数字`：154 句
- `发音与朗读`：775 句

都满足“每类至少 50 句”的当前底线。

### 当前真实抓取实验库统计

按 2026-03-19 这轮真实抓取和打散结果，如果也映射到同样的大类，当前约为：

- `日常与出行`：80 句
- `看病与求助`：50 句
- `人群与角色`：80 句
- `设备与数字`：154 句
- `发音与朗读`：775 句

这说明：

- 真实公开来源已经足以支撑训练页现役的 5 个大类。
- `人群与角色` 已经可以正式上训练页，不必继续只留在候选来源池。
- 下一轮重点不再是“有没有句子”，而是继续做白名单清洗，减少帮助页说明语气，补更多课堂/老人/职业的自然句子。

### 工程

- 语料构建固定为两段式：
  1. `fetch`
  2. `clean + split + rank + assign`
- 来源元数据只保留在离线产物和对象存储，不进入前端 UI。
- 抓取失败不能中断整批构建，应该像当前脚本一样跳过并写报告。

### 技术

- 场景分类不能只靠单字关键词，容易误伤；要优先用多字词和 source hint。
- 句子最终是否进监督池，还要叠加：
  - 自动转写一致性
  - 音频质检
  - 抽样人工复核
- `WenetSpeech` 这类大规模自然语音更适合弱监督或预训练，不应与固定文本监督句混用。
