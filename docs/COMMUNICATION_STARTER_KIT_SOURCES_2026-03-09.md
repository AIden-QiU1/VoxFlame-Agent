# 主动沟通 Starter Kit 数据来源（2026-03-09）

这份说明只回答一个问题：沟通页里那组“第一句话”不是拍脑袋写的，它们来自哪些资料、经过了什么改写。

补充说明：这些来源已在 2026-03-09 再次从官方或项目原站点人工核验，页面中的中文句子仍然是结合场景后的改写，不是直接摘抄。

## 1. 设计原则

- 先解决补偿沟通，而不是先追求自由聊天。
- 第一版优先覆盖四个高价值场景：陌生人开口、就医沟通、家人 / 照护、紧急求助。
- 每个场景只保留少量高频开口句，避免把页面重新做成“功能堆砌”。
- 页面里展示的是**中文改写句**，不是直接摘抄英文原句；改写依据来自 AAC、医疗沟通和应急沟通资料中的高频沟通意图。

## 2. 主要来源

1. ASHA AAC  
   https://www.asha.org/public/speech/disorders/aac/  
   用途：确认 AAC 的核心目标不是“聊天”，而是表达 thoughts / wants / needs / feelings / ideas。

2. ASHA Dysarthria In Adults  
   https://www.asha.org/practice-portal/clinical-topics/dysarthria-in-adults/  
   用途：确认构音障碍沟通中的补偿策略，包括预先说明、请求对方给时间、必要时换一种表达方式。

3. Patient Provider Communication - Chinese Simplified Tools  
   https://patientprovidercommunication.org/languages/chinese-simplified/  
   用途：确认医疗沟通板里的高频项应包括 yes/no、疼痛、一般需求、医疗决策等，并且有中文简体工具可参考。

4. Patient Provider Communication - Healthcare Visit Planning Tools  
   https://patientprovidercommunication.org/healthcare-visit-planning-tools/  
   用途：确认医疗场景应强调“直接对患者说”“给足时间”“保留患者本人决策权”。

5. Tobii Dynavox Emergency Response Resources  
   https://us.tobiidynavox.com/blogs/news/emergency-response-resources-for-people-with-communication-disabilities  
   用途：确认应急沟通优先覆盖求助、安全、联系支持者和医疗沟通板。

## 3. 从资料到页面的映射

### 陌生人开口

- 页面目标：先降低误解和尴尬，让用户获得时间和反馈。
- 资料依据：AAC 的 wants / needs / ideas；dysarthria 的补偿式沟通策略。
- 中文改写方向：
  - 先说明“我说话不太清楚”
  - 请求“给我一点时间”
  - 鼓励对方直接反馈“没听清”

### 就医沟通

- 页面目标：优先覆盖疼痛、速度、解释、决策权。
- 资料依据：Patient Provider Communication 的一般需求、疼痛、医疗决策工具；Tobii 的医疗沟通板。
- 中文改写方向：
  - “我需要医生或护士”
  - “我这里疼，请先帮我处理”
  - “请慢一点说”
  - “请先解释清楚，我再决定”

### 家人 / 照护

- 页面目标：减少抢答，让需求和节奏先被听见。
- 资料依据：AAC 基础功能中的 wants / needs / feelings；医疗陪同场景中的直接沟通原则。
- 中文改写方向：
  - “请先听我说完”
  - “我现在想休息一下”
  - “请帮我联系家人”

### 紧急求助

- 页面目标：先发出求助，再说明需要谁、去哪里、怎么做。
- 资料依据：Tobii 应急资源；医疗 / 应急沟通板中的基本求助单元。
- 中文改写方向：
  - “我现在不舒服，需要马上帮助”
  - “请帮我联系急救或报警”
  - “请先带我去安静安全的地方”

## 4. 当前边界

- 这套 starter kit 解决的是“先开口”，不是完整对话脚本。
- 它暂时不替代用户自己的常用短语库；个体高频表达后续进入记忆系统。
- 如果后续扩展到更多中文场景，必须继续沿用“资料来源 -> 场景判断 -> 中文改写 -> 页面验证”的流程。
