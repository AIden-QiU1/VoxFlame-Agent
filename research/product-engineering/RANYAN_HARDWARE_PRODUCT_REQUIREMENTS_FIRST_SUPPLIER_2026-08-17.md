# 燃言多模态 AI 无障碍沟通机 产品功能需求文档

> 首家供应商修订版　V3.0　2026-08-17

## 一、产品战略总纲

### 1.1 产品一句话定义

燃言是一套面向中文构音障碍者的无障碍沟通产品：在用户愿意发声时稳定采集并辅助理解，在用户确认后清晰表达，在网络、识别或外设失效时仍保留文字、短语和大字展示等可靠出口。

### 1.2 产品定位

产品首先解决“用户有表达意图，但陌生人或通用语音识别难以听懂”的现实问题。首要场景是就医窗口、工作与会议、出行、购物、办事和临时求助中的面对面短交流。硬件不是独立堆叠 AI 功能，而是补足手机在稳定收音、清晰外放、实体操作、固定佩戴和持续可用方面的不足。

产品不替用户判断内心，不自动声明疼痛、情绪、诊断或真实意图。系统可以生成草稿和候选，但最终说什么由用户确认。产品定位为沟通辅助，不在未完成分类和验证前宣称诊断、治疗、疾病监测、急救、跌倒报警、导盲或“医疗级效果”。

### 1.3 产品核心宗旨

让用户保有自己的声音、意图和决定权；让一次真实沟通更容易成功，而不是让设备看起来更复杂。

### 1.4 目标用户群体

| 用户群体 | 核心困难 | 优先场景 | 本阶段处理方式 |
| --- | --- | --- | --- |
| 构音障碍者 | 发音含糊、气息弱、语速或音节不稳定 | 就医、工作、出行、购物、办事 | 首要目标用户，进入真实任务验证 |
| 脑瘫、帕金森等伴随言语运动障碍者 | 口齿不清，手持或触控可能受限 | 日常生活、工作、康复协同 | 在构音障碍主任务内验证操作与佩戴 |
| 喉切除或气声用户 | 音量低、声学特征差异大 | 术后生活与社会沟通 | 作为独立声学人群验证，不预设同一算法有效 |
| 完全失语或重度表达障碍者 | 无法依赖自然语音完成输入 | 高频表达、照护、专业 AAC | 文字、短语和替代输入保留；专业 AAC 另立产品线 |
| 失语症及认知语言障碍者 | 词语检索、语序或理解存在困难 | 家庭、康复、社区 | 仅提供可确认候选，不自动重写为用户意图 |
| 听障、视障人群 | 接收或获取信息方式受限 | 特定沟通与环境信息 | 作为后续独立产品能力验证，不并入首代承诺 |
| 沟通伙伴、家属和专业人员 | 不知道如何理解、确认或协助 | 家庭、工作、专业服务 | 仅在用户授权下协同，不代替用户确认 |

### 1.5 产品运行原则

| 原则 | 产品要求 |
| --- | --- |
| 用户确认优先 | 系统草稿、候选和自动补全不得越过用户直接对外表达 |
| 快速出口常在 | 无网、未登录或在线服务故障时，文字发声、常用短语和大字展示仍可使用 |
| 手机继续承担计算 | 首代硬件只负责收音、外放、实体控制和设备状态，不在外设中复制账号、模型和会话系统 |
| 一次只增加一个主要变量 | 先证明音频桥价值，再分别验证独立机、离线、视觉、专业 AAC、机构网关和穿戴显示 |
| 参数服从任务 | 芯片、内存、电池、麦克风和传感器由固定工作负载与真实任务冻结，不以配置表本身定义产品力 |
| 可停止、可替换 | 每阶段必须有不通过条件；供应商、器件和软件资产应可迁移，不形成不可退出的私有锁定 |

## 二、全模块详细功能需求

### 2.1 模块 1：快速表达与故障降级

该模块是任何网络和 AI 能力失效时仍可使用的基础表达层，不依赖外设始终在线。

| 编号 | 功能点 | 需求描述 | 验收要求 |
| --- | --- | --- | --- |
| 1.1 | 常用短语 | 用户无需登录和联网即可选择常用短语并发声；支持编辑、排序和删除 | 100 次调用无阻塞；点击至首音频 P95 目标不高于 300ms |
| 1.2 | 文字发声 | 用户输入或编辑文字后主动发送；支持停止、重放和音量调整 | 未确认内容不得自动播报；播放失败有可见原因和重试 |
| 1.3 | 面对面大字 | 将同一确认文本以大字交给对方阅读 | 音频不可用时仍可完成核心任务；横竖屏可读 |
| 1.4 | 一键降级 | 在线理解、网络或外设失败时，一步切换到文字、短语或大字 | 不出现“外设失败即完全失声”的单点故障 |
| 1.5 | 个人资产恢复 | 常用短语、设置和授权记录可备份、导出、恢复和删除 | 更换手机或硬件后可恢复；不以账号锁定代替数据保护 |

### 2.2 模块 2：实时沟通闭环

实时沟通遵循“采集表达—形成草稿—用户确认—交付对方—失败恢复”的完整闭环。

| 编号 | 子功能 | 详细需求描述 | 触发与反馈机制 |
| --- | --- | --- | --- |
| 2.1 | 稳定收音 | 支持 5—10cm 近讲和 20—30cm 胸前两种姿态；明确输入、静音、路由和故障状态 | App 与外设状态一致；不得只显示笼统“已连接” |
| 2.2 | 识别与意图草稿 | 结合用户授权的热词、场景和个人材料形成可确认文本 | 报告网络、设备和噪声条件下的 P50/P95；不得承诺无条件固定延迟 |
| 2.3 | 低确定性澄清 | 识别不确定或内容后果较高时，提供候选、关键词重说或文字修改 | 不使用统一置信度阈值控制所有用户；不确定时不直接代说 |
| 2.4 | 用户确认 | 支持编辑、候选选择、重说、撤销和重新确认 | 确认动作清楚、可逆；误触不直接造成对外表达 |
| 2.5 | 一致输出 | 外放、大字和复制共享同一份已确认内容 | 不允许不同出口自行改写语义 |
| 2.6 | 打断与恢复 | 用户通过实体键或界面停止播报，随后继续同一沟通 | 动作至扬声器静音 P95 目标不高于 250ms；100 次测试 |
| 2.7 | 故障可见 | 网络差、路由错误、外设异常和服务不可用均提供可理解状态 | 不静默失败，不用模糊等待动画掩盖不可恢复状态 |

### 2.3 模块 3：个人化与训练回流

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| 3.1 | 个人表达准备 | 用户可维护常用短语、热词、场景材料和表达偏好，并知道本次会话使用了哪些内容 |
| 3.2 | 用户修正 | 修正结果可成为产品改进候选；原始音频、转写和训练用途分别授权，不默认长期保存 |
| 3.3 | 训练反馈 | 报告系统是否听清、常见混淆、稳定性、节奏和收音问题；不自动生成医学严重度或治疗结论 |
| 3.4 | 版本与回滚 | 模型、词表和配置均有版本、发布记录、回滚和删除路径；更新失败不破坏离线表达 |
| 3.5 | 数据迁移 | 个人短语、材料和设置支持同账号恢复及受控导出；不承诺未验证的跨品牌完整模型迁移 |

### 2.4 模块 4：多感官反馈与无障碍适配

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| 4.1 | 非单一感官状态 | 关键状态组合文字、位置、节奏、声音或触觉，不只依赖颜色或提示音 |
| 4.2 | 实体操作 | 开始/确认、停止/打断、快捷表达三项动作可盲操作，位置或形状可区分，误触可撤销 |
| 4.3 | 单手与动作受限 | 支持单手、不同握持和候选外接开关；不能满足的人群明确边界，不笼统宣称全人群适配 |
| 4.4 | 状态可调 | 提示音、振动、亮度和公开状态可调节或关闭，避免公开场合暴露隐私 |
| 4.5 | 关键情形恢复 | 低电、无网、锁屏、来电、更新和外设故障均有明确出口，不把恢复责任只写入说明书 |

### 2.5 模块 5：隐私、安全与生命周期

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| 5.1 | 分项授权 | 麦克风、摄像头、位置、原始音频、训练上传和伙伴访问分别授权、可见、可关闭、可撤销 |
| 5.2 | 最小采集 | 外设默认不保存账号令牌、表达正文和原始音频；设备健康数据与用户表达数据分离 |
| 5.3 | 安全更新 | 固件和软件支持签名更新、失败回滚、漏洞响应、组件清单和支持期限 |
| 5.4 | 量产安全 | 每台设备唯一标识；密钥注入受控；量产调试口关闭或受控；返修解锁有审批和记录 |
| 5.5 | 停产与退役 | 明确停产通知、备件、数据删除、软件支持和无法修复漏洞时的缓解或退役方案 |

### 2.6 模块 6：沟通伙伴与服务协同

| 编号 | 功能点 | 需求描述 |
| --- | --- | --- |
| 6.1 | 伙伴协助 | 经用户授权后协助准备材料、学习沟通策略和排障；不能默认读取全部会话或替用户确认 |
| 6.2 | 权限边界 | 编辑、查看、设备维护和机构管理分开授权；消费账号体系不得直接用于医院或机构多租户 |
| 6.3 | 支持材料 | 覆盖开关机、充电、携带、清洁、低电、无网、故障降级、更新、返修和联系支持 |
| 6.4 | 售后闭环 | 序列号关联固件、批次、EOL、返修和投诉；高频故障进入产品改进，不只换机结案 |

## 三、硬件形态与设计规范

### 3.1 硬件设计哲学：去病耻化、可恢复、可维修

外观应接近日常可靠电子产品，避免病人模式、严重度指示和不必要的医疗化语言。用户在连接失败、输出错误或误触后，应能在两步内回到文字、短语或手机外放。按键、挂绳、夹具、扬声器、电池和线缆等高损耗件必须有维修或更换策略。

### 3.2 当前产品形态

| 阶段 | 产品形态 | 主要任务 | 当前决定 |
| --- | --- | --- | --- |
| P0 | 手机与现成近讲麦、外放、固定件、按钮组合 | 证明硬件是否比裸手机更有价值 | 不定制主板；先完成真实任务 A/B |
| G1 | 燃言随身音频桥 | 固定收音距离、清晰外放、实体恢复、设备状态 | 当前唯一近期自研候选；手机继续承担计算与网络 |
| G2 | 联网独立沟通机 | 为无法稳定使用自有手机的人群提供独立设备 | 只有“脱离手机”被验证为刚需才立项 |

### 3.3 G1 主机核心参数

| 项目 | 规格要求 | 冻结方式 |
| --- | --- | --- |
| 控制平台 | ESP32-S3-WROOM-1-N16R8（16MB Flash、8MB PSRAM）或同等级平台为候选；不承担完整 AI | 以 USB、功耗、供货、维护和量产经验选择，不以型号先行 |
| 主连接 | USB-C 标准音频与控制为基础方案；BLE 只作为经验证的辅助控制 | 100 次插拔/重连、30 分钟会话、锁屏、来电、切换 App 和重启 |
| 音频输入 | 可更换近讲麦；数字 MEMS 候选 SNR 不低于 65dBA、AOP 不低于 120dBSPL | 以整机两距离、安静/65dBA 噪声、爆破音、削波和批次一致性冻结 |
| 音频输出 | 单前向语音扬声器与带保护功放；手机外放作为降级 | 1m 舒适档目标不低于 72dBA，最大工作档 80—85dBA，THD+N 目标小于 5% |
| 实体按键 | 开始/确认、停止/打断、快捷表达三键 | 目标用户盲操作、误触撤销、寿命和 EOL 验证 |
| 电池 | 1,500—2,000mAh 候选，具备保护、温度、循环和运输资料 | 固定混合工作负载目标不低于 8h；容量由结构和功耗实测冻结 |
| 结构 | 胸夹或挂颈主体，可更换固定件和近讲麦 | 主体 90—130g、IP54、1.2m 跌落均为样机目标，不作现状承诺 |
| 维护 | 可读取硬件/固件版本、电池、连接、音频状态、重启原因和故障码 | 不记录表达正文；常见故障无需拆机恢复 |

### 3.4 软硬件责任边界

| 系统层 | 承担内容 | 禁止内容 |
| --- | --- | --- |
| G1 外设 | 采音、外放、按键、状态、设备健康、固件更新与恢复 | 保存账号；独立运行完整识别、语言模型、语音合成或在线会话；自行上传音频 |
| 手机应用 | 权限、音频路由、实体事件映射、用户确认、离线短语和故障降级 | 把供应商私有状态建立成第二套业务事实源 |
| 在线服务 | 会话编排、在线理解和结构化响应 | 依赖某家供应商私有协议才能完成核心表达 |
| 用户资料 | 个人短语、材料、偏好和授权记录 | 被设备本地配置无提示覆盖 |

## 四、合规、质量与安全规范

| 领域 | 规范要求 |
| --- | --- |
| 预期用途 | 首版表述为沟通辅助；诊断、治疗、疾病监测、急救和医疗效果另行分类评估 |
| 中国市场 | 结合最终形态确认 GB 4943.1-2022、GB 31241-2022、EMC、SRRC、CCC、RoHS 和电池运输等适用性 |
| 人因 | 明确用户、环境、关键任务、可预见使用错误、形成性评估和最终验证；能靠设计预防的错误不推给说明书 |
| 隐私与网络安全 | 最小权限、分项授权、签名更新、回滚、组件清单、漏洞响应、密钥和调试口管理 |
| 质量追溯 | 需求、风险、设计输入、实现、验证和变更可追溯；每台设备关联关键批次、固件、EOL 和返修 |
| 器件变更 | 麦克风、扬声器、功放、MCU、音频桥、电芯、连接器和关键材料不得未经批准替换 |
| 宣传边界 | IP 等级、续航、声压、效果、首创和医疗级等表述必须由适用测试或正式结论支持 |

## 五、产品迭代路线图

| 阶段 | 产品主题 | 核心交付 | 候选平台与规格 | 进入条件 |
| --- | --- | --- | --- | --- |
| P0 | 现成设备验证套件 | 近讲、外放、固定、实体控制的交叉 A/B | 现役 Android 手机与 COTS 配件 | 固定任务、样本、失败分类和停止条件 |
| G1 | 随身音频桥 | 稳定收音、外放、三键、设备健康 | ESP32-S3-WROOM-1-N16R8 或同级控制平台；1,500—2,000mAh 候选 | P0 证明净增益、愿意携带和支付信号 |
| G2 | 联网独立沟通机 | 脱离手机的完整在线沟通 | 成熟 Android ODM 优先；RK3566 + 4GB/64GB 或 QCM6490 平台为候选组合；5,000—6,000mAh 候选 | 一类核心用户持续因手机依赖失败 |
| G3 | 有限离线韧性版 | 弱网下短语、文字发声、检索及经验证的本地理解 | RK3588S + 8GB/128GB 或 QCM6490 平台为候选组合；6,000—7,000mAh 候选 | 网络是主要失败原因，本地正确率、热和功耗同时通过 |
| G4 | 视觉增强版 | 用户主动拍摄的 OCR 和视觉上下文 | 8—16GB/128—256GB；双摄候选；物理遮挡或断电 | 纯音频瓶颈明确，视觉输入有稳定净增益 |
| G5 | 专业 AAC | 眼动、开关、支架、keyguard 和替代输入 | 10—12 英寸、12GB/256GB 和至少两路开关输入均为候选配置 | 有目标人群、专业团队、支付和服务路径 |
| G6 | 机构与电话网关 | SIP/PSTN/WebRTC、租户隔离、审计和运维 | N100 级、16GB/512GB、双网口和 UPS 为容量候选 | 有设计伙伴、采购负责人和运维合同 |
| G7 | 轻量穿戴显示 | 免手持展示确认文本或字幕 | 手机或 G3/G4 提供计算；目标低于 75g、4—6h | 低头看屏是明确障碍且用户愿意长期佩戴 |

P0、G1、G2 是一条证据链；G3—G7 是按不同用户与场景拆分的条件产品线，不是必须连续开发的七代产品，也不构成自动排期、预算或采购数量承诺。

## 六、商业与工程落地要求

### 6.1 完整成本口径

项目评审不能只看 BOM。报价与经营模型必须同时覆盖出厂价、包材、运输、入库抽检、软件或许可、NRE、工业与结构设计、模具、工装、认证、测试设备、良率损耗、库存与账期、售后换新、固件维护、备件和退市。所有免费项和后续收费条件必须写入报价。

### 6.2 开发阶段与退出条件

| 阶段 | 核心工作 | 必须交付 | 不通过条件 |
| --- | --- | --- | --- |
| P0 | 现成组合与真实任务验证 | 原始数据、失败样本、佩戴与支付反馈 | 相对裸手机无稳定净增益，或故障和负担抵消价值 |
| EVT0 | USB、音频、控制和功耗风险样机 | 框图、关键器件、功能板、协议、日志和风险清单 | 关键路由不可诊断或必须频繁人工重启 |
| EVT1 | 可佩戴结构与声学迭代 | 两种结构、两种近讲配置、声学/热/续航数据 | 佩戴负担抵消沟通增益，结构与声学冲突无解 |
| EVT2 | 小批目标用户样机 | 建议不少于 10 台、全序列号追溯、兼容矩阵 | 相对 P0 最佳现成方案没有额外价值 |
| DVT | 设计冻结与可靠性 | EMC/射频预扫、ESD、电池、跌落、清洁、寿命、OTA 和法规计划 | 关键失效只能靠说明书规避，成本或供货失控 |
| PVT | 生产验证 | 线体、工装、EOL、良率、追溯、包装、返修和备件 | 无法定位批次、EOL 不能覆盖完整音频链或资产不移交 |

### 6.3 供应商核心交付

供应商需按阶段交付需求偏离表、系统框图、风险清单、BOM/AVL、原理图、PCB/Gerber/堆叠、结构 CAD、材料与表面处理、声学设计、固件源码与构建说明、协议、测试工具、测试计划和原始数据、问题清单、变更记录、EOL 工装与软件、黄金样、组件清单、许可证、密钥流程、包装和维修资料。定制资产的所有权、使用权、转厂权和合作终止后的移交方式必须在合同中逐项约定。

## 七、产品核心优势总结

| 维度 | 燃言方案 |
| --- | --- |
| 用户价值 | 以真实沟通是否成功为首要结果，识别分数和芯片配置只作为支持指标 |
| 表达权 | AI 形成草稿，用户确认后才对外表达；失败时有文字、短语和大字出口 |
| 硬件策略 | 先用 P0 证明硬件增益，再开发 G1；不从高算力独立机倒推需求 |
| 工程边界 | 外设、手机、在线服务和用户资料职责明确，不建立供应商私有业务主链 |
| 产品演化 | G2—G7 各自有用户、支付、工程和责任门槛，不因编号自动获得投入 |
| 量产能力 | 从需求、风险、验证到器件批次、EOL、返修和退役全程可追溯 |
| 商业可控 | 比较完整落地成本、供货和资产迁移，不以最低 BOM 或一次性样机成功做决定 |

燃言硬件产品的核心不是功能数量，而是把“用户表达—系统理解—用户确认—可靠交付—失败恢复”做成一条长期可验证、可量产、可维护的产品链。任何芯片、传感器和 AI 功能只有在这条链上产生可测量价值，才进入产品。
