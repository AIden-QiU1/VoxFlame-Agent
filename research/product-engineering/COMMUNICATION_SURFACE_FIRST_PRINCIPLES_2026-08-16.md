# 沟通 Surface 第一性原理收口

> 日期：2026-08-16
>
> 状态：已进入 Web 最小切片；Mobile 尚未对齐。

## 用户真正要完成的事

用户不是来“选择 agent”或“配置场景”的，而是要把一句话可靠地交给对方。系统只有在完成这个目标所需的能力不同，才应切换执行方式：

1. 已知文字、只需替用户说出：浏览器或设备本机朗读即可。
2. 用户需要开口，系统要识别非标准语音、结合个人上下文纠错并持续对话：才启动 LiveKit agent。

这两种方式属于同一个 `/communicate`，不是两个产品页面。

账号也只应在能力需要时出现：通用短语和手动文字只依赖本机朗读，因此匿名打开即用；个人短语、workspace 记忆和持续语音理解需要用户身份，只有使用这些个性化能力时才要求登录。临时求助不能先被注册流程拦住。

## 页面职责

| Surface | 唯一职责 | 不承接 |
| --- | --- | --- |
| 沟通 | 使用快速短语；按需启动日常沟通 agent；呈现 confirmed output | 场景模板、材料和个人短语的长期编辑 |
| 记忆 | 维护画像、场景模板、热词、策略、自定义材料和个人短语 | 实时 RTC 会话和训练报告 |
| 练习 | 数据录入与有目标的表达练习 | 医学诊断、重复维护沟通场景 |
| 健康筛查 | 固定任务下的系统听清、音系、节奏、静音、收音和个人趋势反馈 | 医学严重度自动判定、另建自由表达入口 |

## 唯一数据流

```text
记忆页维护 workspace
  -> 快速表达读取个人短语，本机朗读，零 agent
  -> 日常沟通读取默认模板 / 当前材料 / 画像
       -> 用户明确开始后连接 LiveKit agent
       -> ASR + 意图纠错 + 连续上下文 + confirmed output
```

## 本次删除和约束

- 删除 `/chat` 和 `/communicate/live`，不保留兼容跳转。
- 删除固定六场景选择页及其前端大卡组件/数据。
- 快速短语点击不再先连接 agent 或把文字发给 agent。
- `/communicate` 不再整页强制登录；匿名用户可直接使用通用短语和手动输入，点击日常沟通时才进入登录流程。
- `ChatInterface` 与 LiveKit 工作台按需拆包，匿名快速表达不预先下载整套强助手代码；本轮生产构建的 `/communicate` First Load JS 从约 `355 kB` 降至 `209 kB`。
- 日常沟通不再显示场景大卡、短语抽屉、连接诊断和手动资料勾选。
- workspace loadout 仍是资料事实源；记忆页的已选模板和当前材料自动成为默认上下文。
- 快速短语的使用面在沟通页，增删改面在记忆页；两者复用同一 `quick_phrases` 数据源。

## 验证门槛

1. Next.js 生产路由表只有 `/communicate`，没有 `/chat` 或 `/communicate/live`。
2. 匿名访问 `/communicate` 返回页面本身；匿名访问两个旧 URL 直接 404，不经过登录或新页面。
3. 未进入日常沟通前不挂载 RTC hook，不创建 RTC session。
4. 快速短语和手动文字通过本机 `speechSynthesis` 播放。
5. 日常沟通只有用户明确点击后才要求登录并挂载 `ChatInterface`。
6. 已选场景模板和当前材料按 workspace `default_selected` 自动进入 preparation context。
7. 真实账号仍需完成个人短语、LiveKit 连接、麦克风、confirmed output 的端到端 smoke；真实设备仍需确认系统 TTS 有声输出。
