# 燃言多模态 AI 无障碍沟通机 产品方案

> 通用供应商版　V1.0　2026-08-17

## 一、产品概述

### 1.1 产品定义

燃言是一套面向中文构音障碍者的无障碍沟通产品。系统在用户愿意发声时稳定采集并辅助理解，在用户确认后通过语音或文字清晰交付，在网络、识别或外设失效时仍保留文字发声、常用短语和面对面大字等可靠出口。

产品第一阶段聚焦仍有自然语音、但陌生人或通用语音识别经常听不懂的用户，优先解决就医、工作、出行、购物、办事和临时求助中的短时沟通。产品定位为沟通辅助，不在未完成分类和验证前宣称诊断、治疗、疾病监测、急救、导盲或医疗效果。

### 1.2 产品目标

| 目标 | 衡量方式 |
| --- | --- |
| 提高真实沟通成功率 | 固定任务是否完成、第一次即理解、重复次数和完成时长 |
| 降低失败恢复成本 | 网络、路由、识别或硬件故障后能否迅速切换表达出口 |
| 保留用户表达权 | 未经确认的草稿不对外播报；误触可撤销；高后果内容必须确认 |
| 形成长期可用产品 | 用户是否愿意携带，设备是否易清洁、维修、更新和迁移 |
| 建立可经营硬件 | 完整落地成本、供货、良率、售后和生命周期是否成立 |

### 1.3 系统组成

| 系统层 | 主要职责 | 边界 |
| --- | --- | --- |
| 随身外设或独立设备 | 收音、外放、实体控制、状态和设备健康 | 不擅自保存账号、表达正文或上传音频 |
| 燃言手机应用 | 权限、音频路由、用户确认、离线表达、设备管理和故障降级 | 业务动作由明确协议驱动，不依赖私有黑盒 |
| 在线服务 | 会话编排、在线理解和结构化响应 | 不能成为无网时唯一表达出口 |
| 用户资料 | 常用短语、场景材料、偏好和授权记录 | 用户可查看、导出和删除，不被设备状态覆盖 |

## 二、产品功能方案

### 2.1 快速表达

| 编号 | 功能 | 需求 |
| --- | --- | --- |
| F1 | 常用短语 | 无网、未登录也可调用；支持编辑、排序、删除和本机发声 |
| F2 | 文字发声 | 用户主动发送，支持停止、重放和音量调整；未确认内容不得自动播报 |
| F3 | 面对面大字 | 同一确认文本可转为大字展示，音频失败时仍可完成沟通 |
| F4 | 快速降级 | 在线服务或外设失败时，一步切换到文字、短语或手机外放 |
| F5 | 资产恢复 | 个人短语、材料和设置可备份、导出、恢复和删除 |

### 2.2 实时沟通

| 编号 | 功能 | 需求 |
| --- | --- | --- |
| F6 | 稳定输入 | 支持近讲和胸前姿态，明确输入、静音、音频路由和故障状态 |
| F7 | 草稿生成 | 结合用户授权的热词、场景和材料形成可确认文本 |
| F8 | 澄清与修改 | 不确定时提供候选、关键词重说、文字编辑和撤销，不直接代说 |
| F9 | 确认内容 | 语音外放、大字和复制共享同一份用户确认内容，不在出口再次改写 |
| F10 | 打断恢复 | 实体键和界面均可停止播放；动作至静音 P95 目标不高于 250ms |
| F11 | 故障可见 | 网络、服务、外设、电量和升级异常给出可理解原因与恢复路径 |

### 2.3 个人化、训练与协同

1. 用户维护常用短语、热词、个人材料和表达偏好，并知道当前会话使用了哪些内容。
2. 用户修正可形成改进候选，但原始音频、转写和训练用途分别授权，不默认长期保存。
3. 训练反馈只说明系统听清、稳定性、节奏、常见混淆和收音问题，不自动给出医学严重度或治疗建议。
4. 沟通伙伴可在用户授权下协助准备和排障，但不能默认读取全部会话或替用户确认。
5. 机构版本必须另行建立角色、租户隔离、审计、留存、录音告知和运维边界。

### 2.4 无障碍、人因与隐私

| 领域 | 需求 |
| --- | --- |
| 状态反馈 | 关键状态不得只依赖颜色或声音，应组合文字、位置、节奏、声音或触觉 |
| 实体操作 | 核心按键位置或形状可区分，支持单手和盲操作，误触可撤销 |
| 故障恢复 | 低电、无网、锁屏、来电、升级和外设异常均有明确出口 |
| 权限 | 麦克风、摄像头、位置、原始音频、训练上传和伙伴访问分别授权与撤销 |
| 数据 | 外设默认不保存账号令牌、表达正文和原始音频；日志不记录个人表达内容 |
| 生命周期 | 软件与固件支持签名更新、回滚、组件清单、漏洞响应、支持期限和退役 |

| G5 | 专业 AAC | 眼动、开关、支架和替代输入 | 10—12 英寸、12GB/256GB、keyguard 和至少两路开关输入均为候选配置 | 目标人群、专业团队、支付和服务路径成立 |

## 四、当前优先产品：G1 随身音频桥

### 4.1 产品形态

G1 是与 Android 手机配合使用的胸夹或挂颈式音频外设，可连接可更换近讲麦，配置面向沟通伙伴的扬声器、三个可盲操作实体动作、非单纯依赖颜色的状态反馈、充电和有线数据接口。手机继续承担账号、权限、在线会话、识别、确认、语音合成、个人资料和上传。

### 4.2 架构与规格输入

| 子系统 | 需求 | 供应商应说明 |
| --- | --- | --- |
| 主连接 | USB-C 标准音频与 HID/控制为基础方案；BLE 只作经验证的辅助 | Audio Class、采样率/位深/通道、电源角色、枚举、兼容和恢复行为 |
| 控制平台 | ESP32-S3-WROOM-1-N16R8（16MB Flash、8MB PSRAM）或同级为候选 | 选择理由、量产案例、功耗、供货、源码、维护和替代方案 |
| 音频桥 | 优先评估专用 USB audio codec/bridge；合并方案须通过压力测试 | 时钟、全双工、Android 路由、诊断、AEC/降噪位置和许可证 |
| 麦克风 | 可更换近讲路径；候选 SNR 不低于 65dBA、AOP 不低于 120dBSPL | 完整料号、两距离、噪声、爆破音、削波、批差和 EOL 方法 |
| 扬声器 | 单前向语音腔体与保护型功放 | 1m 声压、THD+N、频响、回声、温升、功耗、寿命和整机 EOL |
| 按键 | 开始/确认、停止/打断、快捷表达三项动作 | 形状/位置、盲操作、误触、寿命、密封和可维修性 |
| 电池 | 1,500—2,000mAh 候选，具备保护、温度、循环和运输资料 | 固定工作负载、充电、温升、循环、低电降级和更换策略 |
| 结构 | 胸夹或挂颈，支持可更换固定件和近讲麦 | 重量、体积、声腔、天线、散热、IP、跌落、清洁、装配和维修预算 |

主体 90—130g、固定工作负载不低于 8h、IP54、1.2m 跌落、1m 舒适档不低于 72dBA、最大工作档 80—85dBA 均为样机目标，不是当前已达成规格。最终指标由风险样机、目标用户任务、法规适用性和书面报价共同冻结。

### 4.3 固件与应用接口

最低事件包括开始、停止、快捷表达、音频路由就绪、电池状态和故障码。协议需包含版本、事件类型、单调序号或时间、请求标识、状态值和校验信息，并定义超时、重试、幂等、去重、乱序、断线重连、未知事件和版本不兼容处理。

固件只报告动作与设备状态，不自行保存训练数据、上传音频、拨号、发送消息或调用云端服务。应用可读取能力表、硬件/固件版本、电池、连接、音频状态、重启原因和非隐私故障记录。供应商私有 SDK 如不可避免，需披露许可证、源码或托管安排、维护期限、费用和退出方案。

### 4.4 Android 兼容

EVT 阶段冻结不少于三类代表性 Android 设备和系统版本。每个组合至少完成 100 次插拔或重连、30 分钟连续会话，以及锁屏、解锁、切换应用、来电、通知、低电、系统重启、应用升级和固件升级后的恢复。失败记录必须包含设备型号、系统、应用、固件、时间、路由状态和恢复结果。

### 5.2 生产与变更

1. 提供完整 BOM、制造商料号、AVL、生命周期、MOQ、交期、授权渠道和替代料。
2. 麦克风、扬声器、功放、MCU、音频桥、电芯、连接器、天线和关键材料未经书面批准不得替换。
3. 变更必须评估接口、性能、功耗、声学、可靠性、供货、软件、认证和 EOL 影响，并完成约定再验证。
4. 每台设备关联序列号、硬件版本、固件版本、关键器件批次、生产时间、工位、EOL 和返修记录。
5. 供应商提交黄金样、夹具、限值、校准、测量系统分析或等效方法、测试软件、日志格式和维护计划。

### 5.3 安全与生命周期

| 领域 | 最低要求 |

| 组件 | 提供软件物料清单、开源许可证、第三方 SDK 和已知漏洞处理流程 |
| 支持 | 分别报价固件维护、关键漏洞、Android 兼容、器件停产通知、备件和返修期限 |
| 退出 | 合作终止时明确源码、构建环境、密钥迁移、测试资产、工装、库存和替代供应 |

## 六、合规与宣传边界

最终适用要求需结合产品定型、无线能力、电池、电源、宣传语和销售渠道确认。供应商应逐项说明 GB 4943.1-2022、GB 31241-2022、EMC、SRRC、CCC、RoHS、电池运输及其他要求的适用判断、实验室、样机条件、周期、费用和失败整改责任。

IP 等级、跌落、续航、声压、效果、首创和医疗级等表述，只能在适用方法和证据支持后使用。元器件证书、相似公版证书和预测结果不得表述为燃言整机已通过。若未来预期用途涉及诊断、治疗、疾病监测或医疗效果，另行完成中国法规分类和注册路径评估。
